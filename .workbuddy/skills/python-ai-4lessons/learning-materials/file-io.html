文件读写

概念卡 08 前置：字符串 · for 循环 · 函数 8 道分层自测 6 条可核查来源
60 秒速读

文件读写就是让程序把磁盘上的内容读进来，把结果写回去。

open() 打开文件，with 让它用完自动关闭，比手写 close() 更保险。中文乱码多半是编码不对： 新文件统一用 encoding="utf-8"，遇到老 GBK 文件要显式声明。[1]

💡 通俗理解 · AI 辅助整理 · 本人已核查

文件读写像到档案馆调卷还卷。调卷要报出卷号，管理员按号把卷宗递出来；用完必须还回去， 否则架上会一直挂着未归还的记录。with 就像进馆时登记一次、出馆自动注销，不必惦记还有哪本没还。 档案馆也可能用不同年代的编码造册，老卷宗按新规则读，看到的就全是乱码。

学习目标

  • 能解释 open() 与 with open() 的区别，并说出为什么推荐 with。
  • 能区分读文本的几种方式（一次读完、逐行读、读成列表），并按文件大小选择合适的做法。
  • 能说明中文乱码与 encoding 的关系，并知道遇到 GBK 老文件时怎么处理。
  • 能用 pathlib.Path 与 .glob() 遍历一个文件夹，取出其中所有稿件的路径。

核心问题

手写 close() 也能关文件，为什么还推荐 with？
因为 with 省掉的是"万一出错怎么办"。官方教程的说法是：处理文件对象时最好使用 with 关键字， 它的优点是子句体结束后文件会正确关闭，即便触发异常也可以； 而且比等效的 try-finally 代码块简短得多。[1] 官方还给了一条警告：调用 f.write() 时如果没有用 with、也没有调用 close()， 即使程序正常退出，也可能导致内容没有完整写入磁盘。[1] 对写文件来说，这不是风格问题，而是数据完整性问题。
读中文文件为什么会出现乱码？
因为文件的实际编码和读取时声明的编码不一致。 官方教程建议：除非确定需要用别的编码，否则一律写 encoding="utf-8"， 因为 UTF-8 是现代事实上的标准；不指定编码时用的是与平台有关的默认值。[1] 处理早年的 GBK 老文件，就在打开时显式写 encoding="gbk"； 如果文件里还夹杂个别无法解码的字符，可以用 errors="ignore" 跳过——但要清楚这会丢字符， 廖雪峰教程把它称为"最简单的方式"，并未说它无损。[4]
一次读完整篇，还是逐行读？
看文件大小。官方教程给的判断很实用：文件小，f.read() 一次性读最方便； 不确定大小、或者文件很大，就用循环遍历文件对象逐行读，官方说这种操作"能高效利用内存， 快速，且代码简单"；需要按行列表处理时用 f.readlines() 或 list(f)。[1] 这里的陷阱是：read() 会把整个文件读进内存，几千篇稿件合起来读一次， 程序会明显变慢甚至卡住。
怎么把一个文件夹里的稿件都取出来，而不是一篇篇写路径？
用 pathlib 的 Path 加通配符。glob() 的官方定义是 "解析相对于此路径的通配符 pattern，产生所有匹配的文件"，例如 Path('.').glob('*.py')。[3] 把它和 for 循环组合起来，就是"遍历整个文件夹"： for 路径 in 稿件夹.glob("*.txt"):。 需要注意官方的一条提醒：路径不会以特定顺序返回，需要固定顺序时要自己对结果排序。[3] 做可复现的统计时，这一句很关键。
为什么用路径对象，而不直接拼字符串？
因为路径不是普通文本。官方文档说明，pathlib 提供表示文件系统路径的类， 其语义适用于不同的操作系统；不熟悉该模块时该用的就是 Path， 它在运行代码的平台上实例化为具体路径。[3] 用字符串拼路径，得自己操心分隔符是 / 还是 \； 用 Path，稿件夹 / "2026-05" / "001.txt" 这样的写法在 Windows 和 macOS 上都能跑， 而且路径对象自带 .name、.suffix、.glob()、.read_text() 这些顺手的方法。[3]

结构化解释

是什么

文件读写是让程序和磁盘打交道：把文件内容读进内存变成字符串或列表， 或者把内存里的结果写成文件保存下来。读的时候用 open() 打开文件对象， 常用参数是文件名、模式（'r' 读、'w' 写、'a' 追加）和 encoding； 写的时候用 write() 把字符串落盘。[2] 模式里的 'w' 有个必须记住的后果：同名文件会被覆盖。[1]

为什么

因为程序处理完的东西必须留下来，才能被下一段程序接着用。前面几张卡做的事都在内存里： 变量一关就没了，列表是临时搭的。文件读写是把成果落到磁盘的那一步， 也是"一批材料"变成"一张表"的关键一步。新闻生产里这件事本来就有正式做法： 新闻机构之间交换与归档文本、图片、音视频稿件时用的 NewsML-G2，是国际新闻电信理事会维护的 行业标准，它不只是包裹正文，还要带上元数据、稿件管理信息与打包方式。[6] 换句话说，"稿件怎么存、靠什么认出来"在新闻业里是有标准的；而把一批稿件合并成结构化的表， 是让后续统计与建模有据可依的前提。

怎么工作

读的流程是：打开文件、读取内容、关闭。写文件是同一个流程换个模式。 逐行处理用 for 行 in 文件对象，处理整个文件夹用 Path.glob() 拿路径、 循环逐篇读；把结果写成表格用标准库的 csv 模块， 官方示例在打开文件时写了 newline=''，并提示需要指定编码时传 encoding 参数。[5]

from pathlib import Path
import csv

稿件夹 = Path("稿件/2026-05")
合并表 = []

def 清洗文本(文本):
    """去掉首尾空白与多余标点，供批量处理调用。"""
    文本 = 文本.strip().replace("\u3000", "")
    return 文本.replace("，", ",").replace("。", ".")

for 路径 in sorted(稿件夹.glob("*.txt")):            # 排序，保证每次跑口径一致
    原文 = 路径.read_text(encoding="utf-8")          # 老文件改用 encoding="gbk"
    合并表.append({"文件名": 路径.name, "正文": 清洗文本(原文)})

with open("干净语料.csv", "w", encoding="utf-8", newline="") as f:
    写入器 = csv.DictWriter(f, fieldnames=["文件名", "正文"])
    写入器.writeheader()
    写入器.writerows(合并表)
这张表的去向：本卡产出的 干净语料.csv 是第 3 课与第 4 课的唯一输入。 第 3 课把它变成特征与标签，第 4 课的情感分析也在这张表上跑。表里的列名、清洗口径一旦定下， 后面两课都沿用同一份——所以这一步值得慢慢做，而不是先跑通再说。

应用案例

80 篇稿件，一张表。2026 年 5 月，一个系列报道收尾时，编辑部手上有 80 篇稿件， 分散在一个文件夹里：有的是通讯员发来的 .txt，文件名从 稿1.txt 到 最终版2.txt 什么都有；有的段落开头带全角空格，有的句子里混着半角逗号。 要统计"这组报道里提到某关键词的稿件有多少篇"，第一步不是分析，而是把 80 个文件变成一张能统计的表。

做法是四步：Path.glob("*.txt") 一次取出文件夹里所有稿件路径； 循环逐篇用 read_text(encoding="utf-8") 读成字符串 （遇到早年存的 GBK 文件，就显式改成 encoding="gbk"）；[4] 把正文交给上一张卡写的清洗函数；最后把文件名和清洗后的正文写进 干净语料.csv。[3][5]

有两个细节值得单独记住。第一，glob() 不保证返回顺序， 官方文档明确提示需要特定顺序时应自行排序；[3] 在这个例子里就是 sorted(稿件夹.glob("*.txt"))—— 否则同样一份数据跑两次，表里行的顺序可能不同，后续核对会白白多花时间。 第二，写 csv 时如果用了 DictWriter，列名要事先定清楚， 因为列名一旦定下，第 3、4 课都得跟着它走。[5]

示意

上面的稿件数量、文件名与时间线是课程设计的推演，用于说明批量处理的步骤与陷阱， 不是对某家媒体真实归档流程的记录。可核查的部分是官方与教程给出的规则： with 的优点与写文件警告、encoding 的建议、glob() 返回顺序不固定、 csv 写入时的 newline 与 encoding 参数。[1][3][5]

概念辨析

邻近概念 与本概念的区别 一句话区分点
open() 与 with open() open() 只负责打开，关不关由人记得；with 在语句块结束时自动关闭，出错也会关，并且写入落盘更可靠。 open 是开门，with 是"门会自己关上"。[1]
路径字符串拼接 字符串拼接要自己处理分隔符，换系统就可能出错；Path 的语义在不同操作系统上都成立，还自带 .name、.glob() 等方法。 路径不是普通文本，交给路径对象处理更稳。[3]
二进制模式 'rb' / 'wb' 文本模式读出来是字符串，会按编码解码、并把换行符统一成 \n；二进制模式读出来是字节串，不能指定 encoding。 处理文字用文本模式，处理图片音视频用二进制模式。[1]
内容交换与归档规范
（NewsML-G2）		 行业标准规定内容条目交换时要连同元数据、管理信息与打包方式一起传；本卡做的是把一批本地文件合并成一张表，属于自建的小口径。 行业标准让不同机构认得出内容条目，本地表格让同一批内容条目能被程序算得出来。[6]
