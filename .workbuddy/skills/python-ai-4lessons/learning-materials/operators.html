运算符

补充卡 · 无独立编号 前置：变量与数据类型 8 道分层自测 7 条可核查来源
60 秒速读

运算符就是让数据参与计算和比较的符号。

算术运算符做加减乘除，比较运算符回答「是不是」，逻辑运算符 and / or / not 把几个判断拼起来。 另有赋值、成员、身份三组。先熟算术与比较，后面的条件判断就跟着通了。[1][3]

💡 通俗理解 · AI 辅助整理 · 本人已核查

运算符像编辑台上的量具。尺子量长短，天平称轻重，另有一枚刻着是／否的印章。一篇稿子先被量出字数、 时长、点赞数，再拿去比对——超过八百字吗？来源里有没有本地地名？两个读数用「并且」「或者」接起来， 就成了一个能直接回答是或否的问句。程序不猜，它只按量具的读数往下走。

学习目标

  • 能说出算术、比较、逻辑三组运算符各自回答什么问题，并各写一个例子。
  • 能解释 7 / 2 与 7 // 2 的差别，说清为什么 / 的结果总是小数。
  • 能写出一个组合条件（用 and / or / not），并说清它在什么情况下为真。
  • 能识别两个最常见的坑：浮点数用 == 比较、把 is 当成 == 用。

核心问题

运算符到底有多少种？需要全背下来吗？
按用途分成七组：算术、比较、赋值、逻辑、成员、身份、位运算。入门只需要熟三组—— 算术（+ - * / // % **）、比较（== != > < >= <=）、 逻辑（and or not），它们覆盖了稿件筛选与统计里的绝大多数场景。 官方语言参考里有一张完整的优先级表，位运算、海象运算符 :=、矩阵乘法 @ 也在其中，但都不在本课范围内。[3]
为什么 7 / 2 得到 3.5，而 7 // 2 得到 3？
/ 是真除法，结果一律是浮点数，哪怕能整除（4 / 2 得到 2.0， 不是 2）；// 是整除，只保留商的整数部分，而且方向是向下取整， 不是「截掉小数」。这就是 -7 // 2 得到 -4 而不是 -3 的原因。 官方教程把它称作 floor division。[1]
and 和 or 会两侧都算一遍吗？
不会。两者都采用短路求值：and 左边为假就直接返回左边，右边根本不计算； or 左边为真就直接返回左边。短路有个实际用处——先判断「名单非空」，再判断 「名单里有没有某个值」，可以避免在空数据上继续往下算。[3]
is 和 == 有什么区别？什么时候必须用 is？
== 比较两个对象的值是否相等，is 比较的是「是不是同一个对象」。 [] == [] 为真（内容一样），[] is [] 为假（两个不同的列表）。 风格指南明确要求：与 None 这样的单例比较一律用 is 或 is not， 绝不用 == / !=。[5]
两个数明明相等，为什么 == 给出假？
因为浮点数用二进制存储，像 0.1 这样的十进制小数无法被精确表示，误差累积之后， 0.1 + 0.2 算出的实际值是 0.30000000000000004。官方专门用一章说明这个限制， 并直接给出 0.1 + 0.2 == 0.3 为 False 的例子。[7] 要比较浮点结果，改用「差的绝对值小于一个很小的数」，或者干脆把小数放大成整数来比。
0 < 5 <= 10 这种连写的比较合法吗？
合法，这叫链式比较，等价于 (0 < 5) and (5 <= 10)， 但中间那个 5 只会计算一次。官方教程在「深入条件控制」一节里讲到了链式比较， 以及布尔运算的优先级与短路规则。[6]

结构化解释

是什么

运算符是对数据做运算的符号。同一批数据，用不同运算符就得到不同结果： 算术运算符（+ - * / // % **）产出新的数值，比较运算符 （== != > < >= <=）产出布尔值 True 或 False，逻辑运算符 （and or not）把若干布尔值合成一个新的布尔值。[3] 除此之外还有赋值（= += -=）、成员（in、not in）、 身份（is、is not）三组，前面三组是主力，后三组按需用。[4]

一个容易忽略的点：同一个符号对不同类型含义不同。+ 用在两个数字上是相加， 用在两个字符串上是拼接，用在数字和字符串之间则直接抛 TypeError——本机实测提示为 can only concatenate str (not "int") to str。[1]

为什么

统计和筛选稿件，本质就是一连串运算：字数要数、比例要算、阈值要比、多个条件要合起来判断。 运算符是这些动作的最小单位——没有它，「这条稿子算不算本地突发」就只能靠肉眼一条条看。 更关键的是可复现：把口径写成一条表达式，同样的输入永远得到同样的结果； 写错了，也只需回改那一行。

怎么工作

一个表达式里同时出现多个运算符时，由优先级决定谁先算。官方参考给出的顺序是 （从高到低）：** → 一元 +x -x ~x → * / // % → + - → 比较（== != > < >= <= is in 等）→ not → and → or。[3] 同一层里从左往右算，括号可以强行改变顺序。

看一个例子："兰州" in 标题 and (时长 >= 60 or 突发)。 解释器先算括号里的比较（in、>=），再算 or， 最后算 and。本卡不要求背下整张表——记住两条就够： 比较先于逻辑，and 先于 or；拿不准就加括号。

标题 = "兰州市轨道交通 2 号线今日开通"
时长 = 92

# 算术：/ 永远返回小数，// 是整除（向下取整）
print(时长 / 60)                # 1.5333333333333334
print(时长 // 60, 时长 % 60)     # 1 32  → 拆成 1 小时 32 分

# + 用在字符串上是"接起来"，不是相加
print("来源：" + "市日报")        # 来源：市日报

# 比较：结果一定是 True 或 False
print(时长 > 60)                # True

# 逻辑：把两个判断拼成一个
是否本地突发 = ("兰州" in 标题) and (时长 >= 60)
print(是否本地突发)              # True

# 坑一：负数整除不是"截掉小数"，是向下取整
print(-7 // 2)                  # -4（不是 -3）

# 坑二：浮点数别用 == 比
print(0.1 + 0.2 == 0.3)         # False

应用案例

一张「稿件时长表」和一次返工的筛选规则。某地市报客户端的后台会导出每篇稿件的 处理时长（以分钟计），编辑部要把它统一成「X 分 Y 秒」的格式。最初有人写成 时长 / 60，拿到的是 1.5333333333333334 这样的小数——既不能直接展示， 也没法拿去和 60 比较。改成 时长 // 60 取整、时长 % 60 取余之后， 92 分钟就稳稳地拆成了 1 和 32。[1] 这两个符号的差别只有一句话：/ 要小数，// 要整数。

同一个脚本里还有一处更隐蔽的问题。编辑想筛出「互动率刚好三成」的稿件，条件写成 互动率 == 0.3，其中互动率由点赞数除以阅读量得到。 结果是这一档长期一条都筛不出来。原因是三成这类十进制小数在计算机里存不精确， 浮点计算的结果与字面量 0.3 并不严格相等——官方文档给出的例子正是 0.1 + 0.2 == 0.3 为 False，实际得到 0.30000000000000004。[7]

修法有两条，都比背规则实用：一是把小数放大成整数再比 （点赞 * 10 >= 阅读量 * 3），二是只做区间判断、不做相等判断 （0.25 < 互动率 < 0.35）。真正要记住的只有一句： 浮点数之间不用 == 判断相等。

示意

上面的编辑部场景为课程推演，不是对某家媒体公开材料的引用。 可核查的部分是运算符自身的行为：/ 返回浮点数、// 向下取整、 0.1 + 0.2 == 0.3 为 False。[1][7]

概念辨析

邻近概念 与本概念的区别 一句话区分点
= 与 == = 是赋值，把右边的值存进左边的名字，是语句； == 是比较，回答两边是否相等，产出布尔值。 一个在存，一个在问。[2]
is 与 == == 比值，is 比身份（是不是同一个对象）。 [] == [] 真而 [] is [] 假。 内容一样不代表是同一个东西；与 None 比较按风格指南一律用 is。[5]
and / or 与 & / | and / or 是逻辑运算，操作布尔值并短路；& / | 是位运算，按二进制逐位处理，两侧永远都会计算。 写在条件里的是 and / or，位运算属于本课的「不教清单」。[3]
/ 与 // / 是真除法，结果总是浮点数；// 是整除，向下取整。 要小数用 /，要整数用 //；负数上 // 的结果可能让人意外。[1]
