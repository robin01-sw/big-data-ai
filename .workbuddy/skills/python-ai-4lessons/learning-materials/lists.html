列表

概念卡 03 前置：字符串 · 变量与数据类型 8 道分层自测 6 条可核查来源
60 秒速读

列表是把一列东西按顺序放在一起，可以随时增删改。

方括号，逗号隔开，位置从 0 起，-1 是最后一项。append() 末尾加一项， len() 数有几项。列表可改，字符串不可改。[1] 里面能放任何东西，split() 的返回值就是列表。[2]

💡 通俗理解 · AI 辅助整理 · 本人已核查

列表就像编辑部墙上的一排稿签：位置是固定的次序（第一张、第二张），但内容随时能换、能抽走、能在末尾补一张。它和字符串最大的区别是「能改」——字符串是刻好的字，列表是白板。列表里可以放任何东西：标题、数字，甚至整本采访记录。还要记住：给列表起第二个名字，两个名字指的是同一块白板。

学习目标

  • 能解释列表"有序"和"可修改"分别意味着什么，并把这两点和字符串作对比。
  • 能区分 append() 与 extend() 的效果差别，以及为什么它们都返回 None。
  • 能写出从一批标题里取出第一条、最后一条、前三条的代码。
  • 能判断什么时候该用列表、什么时候用一个普通变量就够了。

核心问题

append() 和 extend() 到底差在哪？
append(x) 把 x 当成一项加到末尾； extend(y) 把 y 里的内容逐个拆开加进去。 所以 lst.append([3, 4]) 之后列表只多了一项（那一项本身是个列表）， 而 lst.extend([3, 4]) 之后列表多两项。[2] 官方文档给的等价写法很能说明问题：append 相当于 a[len(a):] = [x]， extend 相当于 a[len(a):] = iterable。
为什么 a = b 之后改 a，b 也跟着变？
因为 Python 的简单赋值不会复制数据。写 b = a， 只是让两个名字指向同一个列表。[1] 之后通过任何一个名字改动它，另一个名字"看到"的自然也是改过的样子。 想要一个独立副本，得写 b = a[:]——切片会返回一个新列表。 这一点和字符串不同：字符串改不了，所以不存在这个问题。
列表里真的能放任何东西吗？
能。列表可以放不同类型的元素，也可以放另一个列表（这就成了嵌套）， 当然也能放字典。[4] 但要留意一个副作用：因为内容不统一，就不能对整列做统一操作—— [None, 'hello', 10] 是没法排序的，因为整数不能和字符串比较。[2] 实践中更常见的做法是让一个列表里放同一类东西，比如一整批标题。
split() 和列表是什么关系？
split() 是字符串的方法，但它返回的是一个列表。 这是概念 02 和概念 03 之间那条最关键的连接线： '流感，疫苗，接种'.split('，') 得到 ['流感', '疫苗', '接种']。 有了列表，才能对这一批内容逐个处理——第 2 课的 for 循环就是绕着列表转的。
列表和字符串都有索引和切片，区别在哪？
取值方式几乎一样：都从 0 开始，都能用负数，切片都是含头不含尾。 真正的分水岭是能不能改：字符串是不可变对象，列表是可变对象。[5] word[0] = 'J' 会报 TypeError，而 squares[3] = 64 完全合法。 另外，对列表做切片得到的是一个新列表，不是"视图"。

结构化解释

是什么

列表是用方括号标注、逗号分隔的一组值，是 Python 最常用的复合数据类型。 它有两个关键性质：有序（每一项都有固定位置，可以用索引取）和 可修改（可以原地替换、追加、删除）。[1] 索引与切片的规则和字符串一致，还支持嵌套——列表里放列表， 就像一张二维表格。[1] 列表本身是可变对象，这一点把它和字符串、元组区分开来。[5]

为什么

三个原因。第一，新闻工作里"一批"是常态：一批标题、一批关键词、 一批读者留言、一周的推送记录。用单个变量一条条存，超过十条就没法看了。 第二，列表是"从一条到一万条"的载体：第 2 课的 for 循环、 第 3 课把语料逐条处理，都是绕着列表转的。 第三，列表和字典是机器学习的落地点：概念 10 里"一条样本 = 一组特征 + 一个标签"， 写成代码就是"列表装多条样本、字典描述单条样本"。 换句话说，第 1 课这两个容器，到第 3 课还会原样出现一次。

怎么工作

  1. 建列表：titles = ['A小区改造', 'B桥通车', 'C校开学']，空列表写作 []。
  2. 取一项：titles[0] 是第一条，titles[-1] 是最后一条， 越界会报 IndexError。[4]
  3. 取一段：titles[0:3] 取前三条，返回的是新列表， 不是原来的列表的一部分。
  4. 加内容：append(x) 加一项，extend(y) 加一串， insert(i, x) 插到指定位置。[2][3]
  5. 查信息：len(lst) 数几项，x in lst 判断在不在， lst.count(x) 数出现几次，lst.index(x) 找第一次出现的位置。
  6. 改与删：lst[1] = '新标题' 直接替换，lst.pop() 取走最后一项， del lst[0] 按位置删。[2]
  7. 从字符串来：split() 直接给你一个列表，这是最常用的一步入口。
有一类方法只改列表本身，不返回有用的结果：append、extend、 insert、remove、sort 的返回值都是 None。 官方文档把这条写成一条设计原则：原地修改且不返回特定项的方法，从不返回集合实例本身， 而是返回 None。[2] 所以 titles = titles.append('X') 会把 titles 写成 None，是最常见的初学者事故。
写法会改动原列表吗返回什么
lst.append('新稿')会，末尾多一项None
lst.extend(['甲', '乙'])会，末尾多两项None
len(lst)不会一个整数，表示有几项
'甲' in lst不会True 或 False
lst[1:4]不会一个新列表（浅拷贝）

应用案例

一周的推送记录，两个名字指向同一块白板。 2026 年 5 月，某地级市融媒体中心的新媒体编辑要把一周的推送记录理清楚： 5 天一共 87 条标题，来自三个栏目。她做的第一件事，是把 87 条标题放进一个列表 titles——这一步之后就再也不用数"我存到第几条了"。

接着她想留一份原始副本，于是写了 titles_backup = titles， 然后用 titles_backup.append(...) 往副本里补录漏掉的几条。 补完之后她发现，titles 也跟着变了——85 条变成了 90 条。[1] 原因不是 append 出了问题，而是这一行赋值没有复制任何东西， 两个名字指向的是同一个列表。

正确的写法是 titles_backup = titles[:]，切片会返回一个新列表。[1] 改过来之后，她可以用 len() 分别数两个列表的条数，用 in 检查某条标题有没有重复， 用 append 放心地往副本里补录。三个动作加起来，87 条记录十分钟理完。

示意（推演场景，非公开报道）

上面的人物与数据为教学推演。 "副本没有真正复制"这个问题在真实项目里出现得非常频繁， 排查时往往要花掉比写代码更多的时间——这也是本卡把它写进应用案例的原因。 第 2 课的 for 循环会让这一步变得更自然：逐个判断、分类追加，是列表最典型的用法。

概念辨析

邻近概念 与本概念的区别 一句话区分点
字符串（概念 02） 两者都是序列，索引与切片规则几乎一样。区别在可变性：字符串是刻好的字， 不能原地修改；列表是白板，随时可以改。word[0] = 'J' 报错， lst[0] = 'J' 合法。 字符串不可变，列表可变；这也是 split() 能把前者变成后者的原因。[5]
元组（tuple） 写法上把方括号换成圆括号，取值方式完全一样，但元组一旦创建就不能修改， 也没有 append、insert 这些方法。 要不要改动，决定用列表还是元组。[4]
字典（概念 04） 列表按位置取（第 0 项），字典按名字取（d['标题']）。 列表里可以放字典，字典里也可以放列表。 知道"第几位"就用列表，知道"叫什么"就用字典。
受控词表
（IPTC Media Topics）		 给内容条目标关键词时，行业上用的是一份受控词表——IPTC 的 Media Topics 收录了 1200 多个术语，覆盖 13 种语言，每年至少更新一次。[6] 一条记录的关键词在程序里就是一个列表，但列表里的值必须来自这份词表。 列表管"有几项、什么顺序"，受控词表管"哪些值才算数"。
