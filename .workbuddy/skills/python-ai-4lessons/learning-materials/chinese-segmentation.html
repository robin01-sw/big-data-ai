中文分词

概念卡 11 前置：字符串 · 列表 8 道分层自测 6 条可核查来源
60 秒速读

中文词与词之间没有空格，机器必须自己判断边界。

一句话常有好几种切法，"南京市长江大桥"就有两三种切法。 jieba 有精确、全模式、搜索引擎三种切法，机构名要补自定义词典。 切错会一路传到后面的统计和分类。[1][3]

💡 通俗理解 · AI 辅助整理 · 本人已核查

中文分词像给一长串连在一起的火车车厢重新挂钩。字是车厢，词是编组，但车钩没有标记，得靠经验判断哪几节该挂在一起。同一个序列可能有几种挂法，"南京市长江大桥"可以挂成南京市+长江大桥，也可以挂成南京+市长+江大桥。编组员凭见过的组合来选，遇到没见过的机构名，就得先登记进名册，否则一定会挂错。

学习目标

  • 能解释中文为什么必须分词，而英文一般不需要。
  • 能区分精确模式、全模式、搜索引擎模式的输出差异，并说出各自适用的场景。
  • 能写出一个自定义词典文件，把机构名、人名和专有名词加进去。
  • 能举例说明一次分词错误是怎样一步步传到后面的词频统计和分类结果上的。

核心问题

中文为什么非要分词不可？
因为中文书面语是字连着字写的，词与词之间没有空格。 英文里空格天然划出了词边界，程序照着空格切就行；中文得靠程序自己判断哪几个字该合在一起。[1] 而词是中文里能独立使用的最小单位，后面的词频统计、向量化、分类，全都以词为单位， 所以这一步躲不掉。
"南京市长江大桥"到底该怎么切？
人一眼就知道是"南京市 / 长江大桥"，但程序看到的只是一串没有标记的汉字。 这类句子在术语上叫交集型歧义：存在多个都成立的切分，比如 "南京市 / 长江大桥"和"南京 / 市长 / 江大桥"。[3] 解法不是靠算法"更聪明"，而是靠上下文和词典——把"南京市长江大桥"作为一个整体收进词典，程序就没有机会把它切开。
jieba 的三种模式该怎么选？
看你要的是"准"还是"全"。精确模式试图给出最精确的一种切分，适合文本分析； 全模式把句子里所有可能成词的片段都扫出来，速度很快，但不能解决歧义， 适合做候选词召回；搜索引擎模式在精确模式的基础上把长词再切短， 提高召回率，适合搜索引擎分词。[1] 做词频统计和分类时用精确模式，做检索时用搜索引擎模式。
新闻场景为什么特别需要自定义词典？
因为新闻稿里密度最高的恰恰是机构名、职务名和地名。 默认词典不认识"某某市交通运输局"这样的组合，会把它切成 "某某市 / 交通 / 运输 / 局"，"局"这个字于是挤进词频表前列。 jieba 官方说明写得很清楚：它有一定的新词识别能力， 但自行添加新词可以保证更高的正确率。[1] 而机构名称本身在新闻行业里就是有明文规矩的——第一次出现原则上要用全称。[5]
停用词该不该删？切错了又会怎样？
停用词是"的、了、是、和"这类没有区分力的词，做词频统计或关键词提取时通常要删， jieba 的关键词提取接口支持传入自定义停用词表。[1] 但删的时候要小心，别把有信息量的单字一并删掉——"球""股"单独出现时是有意义的。 至于切错，后果不是一步错、而是一路错：分词错误会直接影响后面的句法和语义处理，并往后传递。[4]

结构化解释

是什么

分词（word segmentation）是把一串连续的汉字切成一个个词，也就是确定词与词之间的边界。 jieba 是中文里常用的 Python 分词组件，官方把它定位为"做最好的 Python 中文分词组件"， 支持精确模式、全模式、搜索引擎模式、paddle 模式四种切法，并支持繁体分词、 自定义词典与词性标注。[1] 一句话说清它的位置：它是整条流水线的第一环。

为什么

两个原因。第一是中文没有天然边界：英文靠空格，中文只能靠算法判断， 而判断必然有出错的可能。[1] 第二是它站在最上游：分词错误会直接影响后续的句法分析与语义理解等模块， 错误一路往后传递。[4] 这意味着同一条错误会以两种方式放大——它会同时污染很多下游指标， 而且往往很难在结果里被发现，因为后面每一步看起来都很正常。

怎么工作

一次完整的处理包含四步：

  1. 选模式切词。精确模式 jieba.cut(s, cut_all=False)、全模式 jieba.cut(s, cut_all=True)、搜索引擎模式 jieba.cut_for_search(s)； 要拿到列表就用 lcut 系列函数。[1]
  2. 先加载自定义词典。用 jieba.load_userdict(文件名)。 词典格式与主词典一致：一行一个词，每行三部分——词语、词频、词性，用空格隔开，顺序不能颠倒， 词频和词性可以省略，文件须为 UTF-8 编码。[1]
  3. 过滤停用词与单字。jieba 的关键词提取支持 jieba.analyse.set_stop_words(文件名)， 它自带的停用词表里既有英文词也有"的、了、和、是、就、都"这类中文虚词。[2]
  4. 交给下游。切出来的词表就是下一步文本向量化的维度来源—— 向量化的每一维都对应一个词。[6]

应用案例

两千条稿子里冒出来的"市长"。 2024 年冬天，某高校舆情小组接了一个活：统计某市三个月内各部门被本地媒体报道的情况， 按部门看哪个被提到的次数最多。他们从本地新闻库里导出两千多条稿子， 用 jieba 默认词典跑了一遍分词，然后统计词频。

第一版结果一出来就不对。词频表前列挤满了"交通""运输""市场""监督""管理"， 单字"局"排进了前十；而他们真正想看的"某某市市场监督管理局""某某市交通运输局" 全都不在表里——因为默认词典不认识这些组合，把它们一片片切开了。 更离谱的是一处误报：一篇关于城市建设的稿子里， "南京市长江大桥"被切成了"南京 / 市长 / 江大桥"， 于是"市长"成了一个凭空出现的高频词，系统把这篇稿子标进了"涉及市领导"的清单。 小组成员翻出原稿核对，稿子里根本没有提到任何领导。

第二版他们做了两件事。第一，建了一个自定义词典文件， 把本市所有部门、主要事业单位、区内主要桥梁和道路的名称按 "词语 词频 词性"的格式写成一行行，用 jieba.load_userdict("userdict.txt") 加载—— 用全称而不是简称，这也正好符合新闻稿首次出现用全称的行业惯例。 第二，改用精确模式做词频统计，把搜索引擎模式只留给检索场景。 重跑之后词频表回到了正常的样子，那张"涉及市领导"的清单也清空了大半。

课堂推演案例（示意，非公开项目）

上例的小组、时间与稿件数量是为说明流程而推演的， 不对应任何可公开查证的真实项目。可核查的部分是机制本身： 自定义词典的格式与用法、"自行添加新词可以保证更高的正确率"、 三种模式的差别，均出自 jieba 官方仓库说明[1]； "南京市长江大桥"的歧义切分出自公开发表的期刊论文[3]； "分词错误会直接影响后续模块"出自公开技术文章，其"约 15% 的句子存在至少一处分词歧义" 这一数字为作者给出的统计，本卡未独立复核，仅作量级参考。[4]

概念辨析

邻近概念 与本概念的区别 一句话区分点
停用词过滤 分词解决"怎么切"，停用词解决"哪些切出来的词不要"。两者顺序固定：必须先切完，才知道有哪些词可以删。 先切再删，不能先删再切。[2]
命名实体识别
（NER）		 分词只确定词的边界；词性标注与命名实体识别在词的基础上进一步判断这个词是名词还是动词、是人名、地名还是机构名。 分词回答"这个词从哪到哪"，NER 回答"这个词是什么"。[1]
搜索引擎分词 搜索场景要尽量不漏，所以用搜索引擎模式把长词再切短以提高召回；文本分析要的是口径稳定，所以用精确模式。 要"全"用搜索模式，要"准"用精确模式。[1]
标注单位的界定 文本标注第一步就要界定"标注单位"是一条记录、一个段落还是一个词；选择"以词为单位"时，词到底怎么界定会直接改变统计口径。 分词就是把"以词为单位"这句话落到可执行的口径上，口径必须写清并保持一致。[5]
文本向量化 分词是向量化的上一环：切出来的词表构成向量空间里的维度，切碎了维度就跟着碎，而且不可逆。 分词决定"有哪些维度"，向量化决定"每个维度填什么数"。[6]
