条件判断

概念卡 05 前置：变量与数据类型 8 道分层自测 7 条可核查来源
60 秒速读

条件判断就是给程序写一条规则：满足就做，不满足就不做。

if / elif / else 从上往下比，第一个成立的分支生效，后面的一律跳过。空字符串、 空列表、0 在 if 里都算假；最容易踩的两个坑是把 = 当成 ==，以及缩进写乱。[2][7]

💡 通俗理解 · AI 辅助整理 · 本人已核查

条件判断像编辑部收稿时的分拣台。稿件先过第一道闸门：来源里有没有本地地名？有就落进本地篮； 没有，稿件继续滑到第二道闸门：标题里有没有本地关键词？第一道闸门放行之后，后面的闸门就不再问。 分拣台严格按事先写好的顺序执行，不猜、不通融，闸门顺序写错，落进篮子的稿件就会跟着错。

学习目标

  • 能解释布尔值只有真（True）和假（False）两种取值，比较运算符的结果都是布尔值。
  • 能区分 = 与 ==，说清哪一个在赋值、哪一个在判断。
  • 能写出 if / elif / else 的三层分流，并说明为什么条件的先后顺序会改变结果。
  • 能判断空字符串、空列表、数字 0 放进 if 里会被当成真还是假。

核心问题

if 后面的条件，能用一句话说完吗？
能，但只能有一个表达式，写多个条件要用 and、or 连起来，例如 if 来源 == '市日报' and '本地' in 标题:。当 if 用来把一个值和多个常量比较时， 官方教程提到 match 语句更合适；对入门阶段的稿件筛选来说，if / elif / else 已经够用。[1] 条件怎么写得更细，官方教程在第 5 章"数据结构"的第 5.7 节「深入条件控制」里集中讲了一层， 包括比较运算的组合与优先级。[4]
为什么把 if 和 elif 的先后顺序换了，结果就不一样？
因为 Python 的执行规则是：条件从上往下判断，某个条件一旦成立，就执行它对应的语句， 然后忽略掉剩下所有的 elif 和 else。[2] 教程里有一个经典例子：先写 age >= 6 再写 age >= 18， 输入 20 会打印 teenager 而不是 adult——因为第一条就把 20 抓住了。写筛选规则时， 把最严格的类目放最前面，是同一个道理的实战用法。
空字符串和空列表为什么在 if 里等于"假"？
这是 Python 的真值测试规则：默认情况下对象都算真，除非它的类型说明自己是假。 官方列出的假值包括常量 None、False，任意数值类型的零（0、0.0）， 以及空序列和空集合（''、()、[]、{}、range(0)）。[3] 所以 if 标题: 的实际意思是"标题不是空字符串"， 而 if 点赞数: 会把 0 个赞的稿件判成假。
写成 if x = 5 会怎样？
Python 会直接报 SyntaxError（语法错误），程序根本跑不起来。 原因是 Python 把 = 定义成语句，不是表达式，所以它不能出现在 if 的条件位置。PEP 572 讲得很直白：C 及其派生语言把 = 定义为表达式， 而 Python 的方式是语句；if (x == y) 与 if (x = y) 语法上极为相似， 语义却截然不同，正是为了区分这两者，Python 后来才为"在表达式里赋值"单独引入了 :=。[7] 真正需要留神的其实是另一半——== 少写一个等号时，得到的不是"判断失效"， 而是整段代码无法运行。
缩进错了一格，为什么程序就不跑了？
因为 Python 用缩进表示"哪些语句属于这个分支"，而不是用大括号。方法体、 if 分支的内容都必须缩进，官方教程原话是"函数语句从下一行开始，并且必须缩进"。[1] 官方风格指南建议每级缩进用 4 个空格，并明确禁止混用制表符和空格。[5] 混用的后果是缩进对不齐，程序抛 IndentationError 或 TabError。

结构化解释

是什么

条件判断是让程序按规则分流的语句：先算一个条件，条件成立就执行一段， 不成立就执行另一段。[2] 它的原料是布尔值（bool）——只有 True 和 False 两个取值； 比较运算符 ==、!=、>、<、>=、<= 以及成员运算符 in 的结果都是布尔值。[3] 把布尔值用 and（都要真）、or（有一个真就行）、not（取反）组合起来， 就能表达"来源是本地媒体，或者标题里提到本地地名"这类业务规则。

为什么

新闻工作里大量判断本来就是规则化的：什么算本地新闻、什么进突发栏、什么稿子要退回补充信源。 靠人一条条记，量一大就会前后不一致。把规则写成条件判断，好处是可复现： 同样的输入永远得到同样的归类，出错时能回到那行代码去改。 这也是人工标注工作的基本要求——类目必须事先定义清楚、判定标准对所有材料一致， 而不是标注员当场临时决定。

怎么工作

执行顺序是理解一切的关键：解释器从上往下逐个算条件，第一个成立的生效， 执行完它下面缩进的语句块后，剩下的 elif 和 else 全部跳过；如果都不成立，才落到 else。[2] elif 是 else if 的缩写，用来避免层层嵌套，可以有零个或多个，else 是可选的。[1]

来源 = "市日报"
标题 = "老城区停车位新增 300 个"

if "市" in 来源 or "老城区" in 标题:      # 条件①：任一成立即命中
    类别 = "本地新闻"
elif 来源 == "省台通稿":
    类别 = "转载"
else:
    类别 = "非本地"

print(类别)   # 本地新闻

应用案例

一条把上千篇稿子分成两堆的规则。某地市报客户端 2026 年 3 月改版后， 后台每天从通讯社、区县通讯员和自媒体渠道收到约 400 篇稿件，其中只有一部分属于本地选题。 编辑原来的做法是逐篇人工扫标题，一个上午过去，人力和注意力都消耗在"看标题"上。

改版后的做法是把判定标准写成一条规则：先把本地地名整理成一张清单 （市名、各区县名、常出现的简称），只要来源里出现清单中的地名，或者标题里出现本地关键词， 就进入本地新闻候选池；两者都不满足的，落到转载或非本地队列。 写成代码就是卡片上方那段 if / elif / else。[2]

规则上线后暴露了两个问题，也正好对应本卡强调的两个点。第一，最初有人把条件写成 if 来源 == "本地"，结果只有来源字段恰好等于"本地"两个字的稿件才命中—— 要判断"包含"就必须用 in 而不是 ==。 第二，把宽泛条件放在最前面（比如 if 来源:，只要来源非空就成立）， 后面的精细条件永远执行不到。[3]

示意

上面的编辑部场景与数字为课程设计时的推演，用于说明规则化筛选的收益与风险， 不是对某家媒体的公开报道。可核查的部分只有规则本身：条件从上往下判断、 第一个成立的分支生效，以及空值被当作假值这两条语言规则。[2][3]

概念辨析

邻近概念 与本概念的区别 一句话区分点
布尔值与比较运算 布尔值是取值只有真、假两种的数据类型；比较运算符是产出布尔值的运算，条件判断是消费布尔值的语句。 比较运算回答问题，条件判断根据答案决定走哪条路。[3]
for 循环 循环解决"同一件事对一批数据做一遍"，判断解决"这件事要不要做、按哪条规则做"。实践中两者经常套在一起用。 循环管重复，判断管分流。[1]
真值判断的省略写法 写 if 标题: 与写 if 标题 != "": 在空字符串上结果相同，但空列表、0、None 也一并被算作假值。 省略写法更短，但它顺手把"空"和"零"都归到了假。[3]
人工标注的规则表 人工标注由标注员按事先定义的类目给材料贴标签；if / elif / else 是把这张规则表写成代码。两者都要求类目互斥、穷尽。 类目重叠时，靠前的类目会把材料先抢走——这与 elif 的执行顺序是同一件事。[6]
