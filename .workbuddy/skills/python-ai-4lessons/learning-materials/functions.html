函数

概念卡 07 前置：条件判断 · for 循环 8 道分层自测 6 条可核查来源
60 秒速读

函数就是把一段做事步骤打包，起个名字，之后随叫随用。

用 def 写一次，之后反复调用；参数是递进去的原料，return 是递出来的结果。 要分清 return 与 print：print 只在屏幕上显示，return 把结果交回给程序继续用。[1]

💡 通俗理解 · AI 辅助整理 · 本人已核查

函数像编辑部的一张通稿模板。模板里把格式写死：先写来源、再写正文、最后附联系方式； 以后每来一条消息，套一次模板就成稿，不必每次重新想格式。模板要改，只改一处， 所有套用它的稿子一起跟着变。递进去的那条消息就是参数，成稿就是 return 交回来的结果。

学习目标

  • 能解释函数把什么封装了起来，并举出一个"改一处、全部生效"的实际例子。
  • 能区分 return 与 print 各自在做什么，并判断调用之后能不能拿到结果继续用。
  • 能写出一个带参数的 def 函数，用能看懂的名字说明它做什么。
  • 能判断一段逻辑该不该封装成函数，说出至少两条判断依据。

核心问题

代码能跑就行，为什么还要包成函数？
因为重复的代码会各自长大。清洗留言的三步——去首尾空格、去多余标点、统一全半角—— 如果在脚本里抄了三遍，某天发现标点规则要调整，就得记住改三处，漏掉一处结果就前后不一致。 包成函数后，改一处、所有调用一起生效；而且函数名本身就是一句说明， 读到 清洗文本(留言) 的人不需要逐行猜这段在干什么。[2]
return 和 print 到底差在哪里？（这是最容易混的一处）
print 是给人看的，return 是给程序用的。 print() 把内容送到屏幕上，函数执行完就结束了，调用处拿到的东西是 None； return 把结果交回给调用它的那一行，可以继续赋值、比较、写进文件。 官方教程在讲函数定义时说得很清楚：return 语句返回函数的值， 不带表达式参数时返回 None，函数执行完退出也返回 None。[1] 典型症状是：函数里写了 print(结果) 却没有 return， 调用处拿到的变量是 None，后面所有基于它的操作都会失败。
参数是什么？不传参行不行？
参数是函数的原料入口。定义时写在括号里的名字叫形参，调用时递进去的具体值叫实参， 两者按位置一一对应。[4] 不传参当然也行，但要区分两种情况：一种是这个函数确实不需要外部输入（比如把当天的日期拼成文件名）； 另一种是"看起来不用传"，其实把关键字写死在函数里了，以后想改就得动函数体。 廖雪峰教程还提醒一个反直觉的点：默认参数必须指向不可变对象， 默认值写成列表这类可变对象，会出现"函数记住了上一次调用"的怪现象。[4]
函数名怎么起才不算白起？
官方风格指南的建议很实在：函数名用小写，必要时用下划线分隔单词， 目的是"提高可读性"。[5] 对新闻场景来说，一个好名字能让代码接近一句业务说明——判断是否本地新闻(稿件) 比 f1(稿件) 有价值得多。另外两条相关建议也值得记住： 变量名沿用同样的约定；不要用 l、O、I 这类单字符名字，因为它们在某些字体里和数字 1、0 长得几乎一样。[5]
什么情况下不必封装？
两种情况不必：只用一次的、只有两三行的逻辑， 硬拆成函数反而让人跳来跳去地读代码。判断方法很朴素—— 如果这段逻辑在第二个地方也需要，或者需要改的时候希望"一改全生效"， 那就封装；如果它只是某个流程里的一个步骤、且不会重复出现，就先让它待在原地。 函数的价值来自复用和统一口径，不是来自数量。教程谈到函数定义时也是这个分寸： 先确定函数名和参数个数，如果有必要再对参数做类型检查[2]—— "有没有必要"靠场景判断，本来就没有一条硬规则。

结构化解释

是什么

函数是一段有名字的操作：定义时用 def 写清函数名、括号里的参数和冒号， 然后在缩进块里写函数体，需要交回结果就用 return。[1] 定义完成之后，函数名就指向这段操作，可以反复调用；也可以把它赋给另一个名字， 两者指向同一个函数对象。[1] 函数是"打包"，循环是"重复"，条件判断是"分流"——第 2 课的三个概念在这里第一次合流。

为什么

因为新闻工作里的规则要可复用、口径统一。一条清洗规则一旦写成函数， 处理 5 条留言和处理 500 条留言用的是同一份实现，不存在"上午清得严、下午清得松"。 这一点在正式的人工标注工作里也有对应：标注手册要把类目定义、判定规则写清楚， 让不同标注员执行同一套标准；把这份手册写成函数，等于把它变成可执行、可复查的版本。 国家标准的标点规范也正是同一类"统一口径"的努力——《标点符号用法》逐条规定了句号、 顿号、问号的形式与位置，还专门增加了使用中文输入软件处理标点的规范。[6] 把这类规则封装进函数，才是几十上百条留言处理起来不走样的前提。

怎么工作

一次调用的完整过程是三步：递参数进来、在函数内部用局部变量干活、 用 return 交结果出去。官方教程说明，函数执行时使用自己的局部符号表， 参数按位置（或按关键字）传进去；一旦执行到 return，函数就结束并返回结果。[1] 需要注意的是 return 和 print 走的是两条路： 前者把值交给调用处，后者只是显示出来。[1]

def 清洗文本(文本):
    """去掉首尾空格、压缩多余标点、统一全半角标点。"""
    文本 = 文本.strip()                      # 去首尾空格
    for 全角, 半角 in {"，": ",", "。": ".", "：": ":", "；": ";"}.items():
        文本 = 文本.replace(全角, 半角)       # 统一标点形状
    文本 = 文本.replace("...", "").replace("!!", "")   # 压缩多余标点
    return 文本                              # 交回结果，而不是打印

干净留言 = [清洗文本(留言) for 留言 in 留言列表]
print("清洗后共", len(干净留言), "条")       # 这才是给人看的输出

应用案例

一个清洗函数，处理几百条留言。2026 年 5 月，编辑部整理一次民生议题讨论的读者留言。 原始材料的模样很难直接统计：有的行首带好几个空格，有的句子里混着半角逗号和全角逗号， 有的末尾拖着一串感叹号或省略号。要统计"提到某关键词的留言有多少条"， 第一步必须先把这些表面差异抹平，否则同一条留言换个标点写法就会被判成两条不同的材料。

第一版脚本把三步操作直接写在循环里，跑通了。第二周要做第二次统计（换成另一个议题的关键词）， 于是把循环体复制过去——问题在这里出现：复制之后有人顺手把"压缩多余标点"那一步删掉了， 两次统计的清洗口径不一样，数字也就没法放在同一张表里比较。 第三版改成了函数：三步写进 清洗文本()，两个统计脚本都调用同一个函数。[2]

这个改动带来的直接好处是"数字可比"。数据新闻手册在讲处理数据的步骤时， 把清洗和标准化列为拿到数据集后的第一件大事，并举过取值不统一的例子： 同一个性别字段里可能同时出现 Male、M、1、MALE 等写法， 不先统一成一套取值，后面的统计就没有意义。[6] 函数的角色正是把"统一"这件事固定下来。

示意

上面的编辑部场景、时间与两版脚本的经过是课程设计的推演， 用于说明"复制代码"与"封装函数"的差别，不是对某家媒体实际作业的记录。 可核查的部分是语言规则：def 定义函数、return 返回值、无 return 时返回 None， 以及官方关于函数命名与默认参数的建议。[1][4]

概念辨析

邻近概念 与本概念的区别 一句话区分点
变量 变量给一条数据起名字；函数给一段操作起名字。两者都"随叫随用"，但一个存值、一个做事。 变量回答"这个值叫什么"，函数回答"这件事叫什么"。[1]
print() print 把内容送到屏幕，属于输出动作，函数本身仍以 None 收场；return 把结果交回调用处，可以被继续使用。 print 是喊给别人听，return 是把东西递到手上。[3]
for 循环 循环负责把同一件事重复若干遍；函数负责把一组步骤命名打包。两者配合的常见写法是"在循环里调用函数"。 循环决定做几遍，函数决定每一遍怎么做。[1]
标注手册 标注手册用自然语言写清类目定义与判定规则；把规则写成函数，等于给这份手册做了"可执行版本"。 手册是给人照着做，函数是给机器照着做，要求都是同一条规则对所有材料一致。[6]
