for 循环

概念卡 06 前置：列表 · 条件判断 8 道分层自测 6 条可核查来源
60 秒速读

for 循环就是让同一件事，对一批数据自动做一遍。

把一批留言交给 for，就会逐条处理一遍。range() 生成序号，enumerate() 同时拿到序号和内容； 循环里删元素会让后面的元素往前挪而漏项，正确做法是另建一个新列表。[1]

💡 通俗理解 · AI 辅助整理 · 本人已核查

for 循环像编辑部把一摞读者留言过一遍。不是把整摞抱起来一次读完，而是抽一张、看一眼、记一笔， 再抽下一张，直到摞空。抽到的每一张就是一次循环，记的那一笔就是循环体里做的事。 摞子的顺序就是清单的顺序，轮到第几张、还剩几张，全由这张清单本身决定。

学习目标

  • 能写出 for 循环遍历列表、字符串、字典的三种写法，并说出每种写法每次取出的是什么。
  • 能区分 range() 与 enumerate()，并判断什么情况下需要序号。
  • 能解释在循环里删除元素为什么会漏项，并写出用新列表的正确做法。
  • 能判断一段循环代码里哪些语句属于循环体（看缩进），并说明 IndentationError 的成因。

核心问题

循环里的缩进，为什么差一格都不行？
因为 Python 靠缩进判断"哪些语句属于这个循环"。缩进相同的语句被认为在同一层， 缩进多一层的才被算进循环体。[5] 官方风格指南要求每级缩进 4 个空格，并明确禁止混用制表符与空格—— 混用会让肉眼看着对齐、解释器读起来不对齐，于是抛 IndentationError 或 TabError。[5] 还有一个常被忽略的推论：把统计或打印语句写在循环体里，它会重复执行一遍； 写在循环外面（不缩进），它才只执行一次。
为什么 range(5) 数出来是 0 到 4，不是 1 到 5？
因为 range() 生成的序列不包含终止值。官方教程的表述是 "生成的序列绝不会包括给定的终止值"。[1] 这正好和列表的下标对齐：长度 5 的列表，合法下标就是 0 到 4。 想让序号从 1 开始显示，用 range(1, 6) 或 enumerate(留言, start=1)。[3]
只想要内容，但还想知道"这是第几条"，怎么办？
用 enumerate()。它每次吐出一个二元组：一个计数和一个值，计数默认从 0 开始， 可以指定 start=1。[3] 官方教程也提到，要按索引迭代序列可以组合 range() 和 len()， 但"大多数情况下 enumerate() 函数很方便"。[1] 写稿时做编号清单、给命中留言标序号，都用得上它。
break 和 continue 差在哪里？
break 是整个循环不要了，立刻跳出，后面的元素一个都不再看； continue 是这一轮不要了，跳过当前元素剩下的语句，直接开始下一轮。[1] 廖雪峰教程还提醒一句实话：这两个语句会造成执行逻辑分叉，容易出错， 大多数循环并不需要它们。[2] 典型的合适用法是"找到第一条命中就停止"——那正是 break 的场景。
在循环里删列表元素，为什么会漏掉东西？
因为删除会让后面的元素整体前移，而循环的下一轮已经走到下一位， 等于跳过一个。官方教程对此的说法很直接："很难正确地在迭代多项集的同时修改多项集的内容"， 更简单的方法是迭代副本，或者干脆创建一个新的多项集。[1] 实战做法是：边遍历边把"要保留的"追加进新列表，遍历结束后用新列表替换旧列表。

结构化解释

是什么

for 循环是让程序对一批数据逐个执行同一段操作的语句。它和 C 语言那种"数数式"循环不同： Python 的 for 是在列表、字符串等序列的元素上迭代，按元素在序列里出现的顺序逐个取用。[1] 每次取出的元素被赋给一个临时变量（习惯叫 留言、稿件、行 这类名字）， 循环体就用这个变量干活。能被 for 逐个取用的东西，叫可迭代对象——列表、字符串、字典、文件对象都是。

为什么

新闻工作里最耗人的从来不是难事，而是重复的事：1000 条留言逐条查关键词、 80 篇稿件逐篇看有没有日期、每天早上把几家来源的标题扫一遍。人做这些事会累、会走神、标准会漂移； 循环不会。循环带来的不只是速度，更是一致的口径： 同一段代码跑 1000 条和跑 10 条，判断标准完全一样。 数据新闻手册里也强调，处理数据前先想清楚要回答哪些问题、变量够不够， 而"清洗和标准化"往往是数据项目里第一件大事[6]——这类工作正是循环最擅长承接的。

怎么工作

三件事要分清楚：从哪里取（要遍历的对象）、取出来叫什么（临时变量）、 取一条之后做什么（缩进的循环体）。取完最后一个元素，循环自然结束，程序继续往下走。 要序号时用 range() 生成数字序列，或让 enumerate() 一次给到序号和内容； 要提前收工时用 break；要跳过某一条时用 continue。[1]

留言列表 = ["老城区停车太难了", "这个政策挺好", "老城区又堵又乱"]
命中清单 = []
关键词 = "老城区"

for i, 留言 in enumerate(留言列表, start=1):   # 序号从 1 开始
    if 关键词 in 留言:
        命中清单.append((i, 留言))             # 只把命中的记进新列表

print("命中数量：", len(命中清单))              # 这句没缩进，只执行一次

同一件事也可以写成一行，这叫列表推导式：

命中清单 = [留言 for 留言 in 留言列表 if 关键词 in 留言]

应用案例

1000 条留言，一条规则，一张清单。2026 年 4 月，一个城市交通议题的系列报道上线后， 客户端后台积了 1000 条读者留言。编辑想知道的不是"有没有人提到老城区"， 而是"到底有多少条、分别是哪几条"——因为这个数字要写进稿子，还要拿来挑引语。

人工做法是逐条读，读到相关的手动复制到另一个文档，同时在心里数数。这样做有三个问题： 数量记不准、中途被打断就要重来、两天后再统计口径可能已经变了。改成循环只需要四步： 把留言装进列表、循环逐条判断关键词是否出现、命中的追加进新清单、循环外打印数量。[1] 代码就是卡片上方那段：enumerate(留言列表, start=1) 让每条命中记录自带编号， 方便回头核对是第几条；len(命中清单) 给出可以写进稿子的数量。

这里有一个容易犯的错：有人先想着"把不相关的删掉，剩下的就是命中"，于是在循环里对原列表做删除。 结果漏项——因为删除之后后面的元素会往前挪，而循环已经走到下一位。[1] 正确做法是反过来的：不动原列表，把要保留的往新列表里放。

示意

上面的留言数量、时间与工作场景是课程设计时的推演，用于说明循环带来的口径一致性， 不代表某家媒体的真实操作记录。可核查的部分是语言规则：range 不含终止值、 enumerate 返回序号与值、迭代过程中修改多项集容易出错并建议改用新多项集。[1][3]

概念辨析

邻近概念 与本概念的区别 一句话区分点
while 循环 for 在一个现成的序列上逐个取用，次数由序列长度决定；while 只要条件成立就一直转，次数事先不一定知道。 for 是"把这一摞过完"，while 是"转到我喊停"。[2]
列表推导式 推导式是"筛出并生成一个新列表"的一行写法，本质还是循环，只是省掉了先建空列表再 append 的步骤。 同一件事的两种写法：循环写给自己看，推导式写给一眼扫过的人看。[4]
遍历字典的三种方式 直接遍历字典拿到的是键；.values() 拿到值；.items() 拿到键值对，最适合"编号配内容"的场景。 要什么就取什么，取错了会拿到键而不是内容。[4]
人工逐条标注 人工标注是标注员逐条读材料、按同一张规则表贴标签；循环是把"逐条"这一步交给程序重复执行，判断规则仍由人写。 循环不会替你定规则，它只保证每条材料用的是同一条规则。[6]
