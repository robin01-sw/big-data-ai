# minute-lesson · 一分钟微课 Skill

## 1. 适用场景（When to use）

调用者想**快速理解并记住一个之前陌生的概念**，并希望产物是单文件 HTML，
方便丢进任何浏览器阅读或放进 Git 仓库长期保存。典型触发：

- 课程笔记：老师/教材提到一个新词（如「Agent」「上下文工程」「Skill」），
  你想要 60 秒看完就能讲给别人听。
- 复习卡：把若干概念整理成同一格式，方便对照记忆。
- 分享材料：发给同学/同事，对方无需任何环境就能打开看。

**不要用本 Skill 的场景**：需要写 5 页以上论文、需要执行真实代码、
需要对比多个竞品做决策。这些请改用更专业的 Skill 或直接和 AI 对话。

## 2. 输入（Input）

调用方需要提供：

| 字段 | 必填 | 说明 |
|---|---|---|
| `concept` | 是 | 想学的概念中文名（也接受英文），如 `Agent` / `大模型的上下文` / `Skill` |
| `slug` | 否 | 文件名 slug，默认基于 `concept` 拼音/小写化生成 |
| `depth` | 否 | `quick`(默认) / `deep`，deep 会多一段「机制深挖」 |

调用方式示例（在 WorkBuddy 里）：

```
/minute-lesson 概念=Agent
/minute-lesson 概念=RAG slug=rag-card
```

也可以直接在对话里说「用 minute-lesson 学习 XXX」。

## 3. 流程（Process）

执行顺序如下，**每一步都是上一步失败时立即中止**的自检点：

1. **核查概念含义（来源真实）**
   - 优先调用 WebSearch 找至少 2 个独立来源（官方文档 > 知名工程博客 > 百科）。
   - **禁止**：仅凭模型记忆写解释。如果搜索失败，明确告诉调用方「来源不可达」并请求指示。
2. **生成 7 段式内容**（结构固定，方便对照记忆）：
   - 学习目标：1 行说清「学完之后能做什么」
   - 核心问题：3-5 个新手最常问的疑问
   - 结构化解释：用「是什么 / 为什么 / 怎么工作」三段，**关键事实后挂角标引用 [^N]** 对应下方来源；并为最核心的机制配 1 张**内联 SVG 示意图**（配色沿用卡片主色、克制，不依赖 CDN）
   - 应用案例：1 个真实具体例子（带场景细节），**关键结论处挂角标**
   - 概念辨析：列出 2-3 个「易混淆」邻居概念 + 区分点，**每条挂角标**
   - 自测题：**8 道分层单选题**（L0 概念识别 / L1 机制理解 / L2 应用判断 / L3 综合对比），各层各 2 题
   - 参考来源：每条来源写明 `标题 + URL + 来源类型`，URL 必须可访问，**至少 5 条**
3. **生成互动式自测（JS 状态机）**
   - 答对 `+1 层`，答错 `-1 层`（最低 L0，最高 L3）。
   - 答错立即在卡片下方显示「正确答案 + 解释 + 来源锚点链接（`📎 来源 → #ref-N`）」，给学习者点一下直接跳到对应来源条目。
   - JS 全部内联，单文件可离线打开。
4. **挂角标引用**
   - 解释段落用 `<sup class="cite"><a href="#ref-N">[N]</a></sup>` 形式就地引用，**N 与参考来源节条目编号一致**。
   - 参考来源节用 `<li id="ref-N">` 锚定，保证锚点跳转能稳定命中。
5. **卡片顶部加渲染版引导 banner**
   - 因为 GitHub 网页对 `.html` 默认显示源码不渲染，需要 banner 引导打开者跳到 GitHub Pages 渲染版或点 Raw。
6. **渲染 HTML（单文件、可离线）**
   - 使用 `template.html` 作为骨架，所有 CSS / JS 内联在 `<style>` / `<script>` 里。
   - 文件落到 `learning-materials/<slug>.html`。
   - 文件**不依赖**任何外网 CDN（除了可选的 Mermaid CDN，离线时降级为文字描述）。
7. **自检（见第 6 节）**：填一张 13 条自检清单，全部通过才认为完成。

## 4. 输出结构（Output）

单文件 HTML，固定骨架：

```
learning-materials/
├── agent.html
├── llm-context.html
├── skill.html
└── concept-relationship.html   ← 可选，三个概念都学完后建议生成
```

HTML 内含以下区块（顺序固定）：

1. 顶部 banner（GitHub Pages 渲染版引导 + Raw 入口）
2. 标题 + 60 秒速读（一句话 + 一段）
3. **💡 通俗理解**（AI 辅助整理的通俗解释，用生活化比喻说清「这是什么/为什么管用」；去第一人称、≤150 字，段落注明「AI 辅助整理·本人已核查」）
4. 学习目标（ul）
5. 核心问题（details/summary，关键结论挂角标）
6. 结构化解释（h3 三段，**就地角标引用 [^N]**）
7. **核心机制示意图**（内联 SVG，1 张，放在结构化解释中机制最核心处；沿用卡片主色、克制用色，不依赖 CDN、断网可显示）
8. 应用案例（h3 + 一个具体故事，**关键数字挂角标**）
9. 概念辨析（表格，**每条挂角标**）
10. 互动自测 8 题（答题 JS 状态机：答对升层 / 答错降层 + 答案 + 解释 + 来源锚点）
11. 参考来源（ol/ul，每条 `<li id="ref-N">` 锚定，**至少 5 条**）
12. 人工核查记录（meta-card）

## 5. 资料来源要求（Source Policy）

- **每条事实必须有可核查的 URL**。禁止捏造链接、禁止用 AI 自生成的「看起来像官网」的链接。
- **优先**：厂商官方文档（openai.com、anthropic.com、workbuddy.cn/docs、kubernetes.io 等）。
- **次优**：知名工程师博客、官方仓库 README、标准化文档（RFC/W3C/MDN）。
- **辅助**：维基百科仅作交叉验证，不作为唯一来源。
- **个人判断**：调用方在 `README.md` 的「人工核查」一节写明哪些解释被自己改写/质疑过。

## 6. 自检清单（Self-Check）

完成生成后，对照下面 13 条逐项打勾（**保持 `- [ ]` 不勾选**，作为 Skill 模板的运行时规则；过程痕迹另存）：

- [ ] 文件落在 `learning-materials/<slug>.html`，文件名和 `concept` 一致
- [ ] HTML 在浏览器中打开能看到 7 + 5 区块（7 段内容 + 顶部 banner + 通俗理解 + 核心机制图 + 互动题区 + 来源节），顺序符合第 4 节
- [ ] 「💡 通俗理解」段在 60 秒速读之后、学习目标之前；去第一人称、含一个生活化比喻、整段 ≤ 150 字，并注明「AI 辅助整理·本人已核查」
- [ ] 「通俗理解」正文用统一字体大小（15px、行高 1.7、正文色），**不加粗**（不用 `<strong>`/`<b>`），不堆术语、口语化、通俗易懂
- [ ] 60 秒速读 ≤ 120 字
- [ ] 至少 1 个真实应用场景（不是泛泛的「可用于……」）
- [ ] 含 1 张「核心机制示意图」（内联 SVG、不依赖 CDN、断网可显示），放在结构化解释中机制最核心处，配色沿用卡片主色、克制
- [ ] 至少 2 个易混淆邻居概念 + 区分点
- [ ] 互动题区恰好 8 道题，且 L0/L1/L2/L3 各 2 道
- [ ] 答错题反馈包含 正确答案 + 解释 + 来源锚点链接（`📎 来源 → #ref-N`）
- [ ] 解释段落 / 应用案例 / 概念辨析段落的**关键事实后**就地挂角标引用，且角标编号与下方来源条目一一对应
- [ ] 参考来源至少 5 条；URL 均经 WebFetch 抽样验证可访问、未伪造
- [ ] HTML 能在断网环境打开（仅 Mermaid CDN 需外网；其余 CSS/JS/图片全部内联）

任意一项不过：不要交付，回去改。

## 7. 复用于其他概念（Reusability）

本 Skill 不绑定 Agent / 上下文 / Skill 三个概念。设计原则：

- `concept` 是唯一必填参数，所有内容围绕它生成。
- 7 段结构对**任何知识概念**都通用：物理、生物、历史事件、协议、框架皆可。
- 如果概念本身是 AI 相关，第 5 节强调「来源必须真实」——AI 概念容易陷入自指循环，
  必须至少有一个**非 AI 公司**的来源做交叉验证。
