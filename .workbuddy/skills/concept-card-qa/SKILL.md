# concept-card-qa · 概念卡批量结构校验

## 1. 何时用

- **批量生成之后**：用 subagent 并行生成 N 张卡，必须有一道机械验收，否则漏项不会被发现
  （实测：一次 17 张卡的批量里，2 个来源从正文消失、1 个 footer 链接指向不存在的文件，
  都是靠这份校验查出来的）
- **批量改写之后**：例如「去术语化」这类跨卡批量编辑，容易连带破坏题库选项与答案索引的对应
- **改模板/规范之后**：确认存量卡片是否仍满足新阈值

**不要用本 Skill 做的事**：来源真伪（必须逐条 WebFetch 实访）、内容准确性、文案质量。
本脚本只回答「结构是否合规」，不回答「内容是否对」。

## 2. 怎么跑

```bash
# 管理版 Python（本机路径固定）
"C:/Users/19623/.workbuddy/binaries/python/versions/3.13.12/python.exe" \
  "<本 skill 目录>/scripts/qa_cards.py" \
  "<learning-materials 目录>"
```

可选参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--plain` | 150 | 「通俗理解」字数上限 |
| `--tldr` | 120 | 「60 秒速读」合计字数上限 |
| `--refs` | 5 | 参考来源条数下限 |
| `--quiet` | — | 只打印失败项，不打指标表 |

退出码：`0` 无硬失败，`1` 有硬失败或死链，`2` 参数/目录有问题。

## 3. 检查项与判级

**硬失败**（阻断交付）：
- 来源条数不足、**角标悬空**、**来源孤立**（列了但正文从不引用）
- 自测题不是 8 道、L0/L1/L2/L3 不是各 2 道、`answer` 索引越界、题干或解析为空
- 题库里的 `ref` 指向不存在的来源编号
- 辨析表 < 3 行、缺内联 SVG、缺 tldr 或通俗理解区块
- 通俗理解含加粗、含第一人称「我」、label 不规范
- footer 缺双返回链接、存在外部 CDN 依赖、标签不配对、站内死链

**告警**（人工判断，不阻断）：
- 速读一句话 > 30 字、一段 > 90 字、合计超上限
- 通俗理解超上限

字数超一点通常是「语义完整性 vs 字数规范」的取舍。**超 2–3 个字建议压缩到合规；超得多说明该重写而不是删字**。

## 4. 两个必须知道的坑（都踩过，脚本里已规避）

### 坑 1：题库正则会被选项里的 `]` 截断

选项文本含转义单引号时，非贪婪匹配会在选项**内部**的第一个 `]` 处提前收尾：

```js
options: [
  'd = [\'标题\', \'正文\']',     // ← 这个 ] 会让下面的写法提前收尾
  ...
],
answer: 2,
```

```python
# 错：4 个选项会被截成 0~2 个，从而误报「answer 越界 / 无选项」
re.search(r'options:\s*\[([\s\S]*?)\]', blk)

# 对：借后面的 answer: 兜住右边界
re.search(r'options:\s*\[([\s\S]*?)\]\s*,\s*\n?\s*answer:', blk)
```

本轮 4 张卡报出的「答案索引异常」**全是这个假警报**。看到这类报错先怀疑解析器，不要急着改卡片。

### 坑 2：不要用 bash 内联 `python -c` 传正则

Windows Git Bash 下反斜杠会被吞（`\{\s*level` 命中 0 次且查不出原因）。
**校验脚本一律写成 `.py` 文件再执行。**

## 5. 改术语的批量任务：子 agent 只会改你指名的范围

想让 subagent 清理某类术语时，**必须把要扫的位置逐项列进 prompt**：

> 正文段落、`<li>` 学习目标、`<details><summary>` 核心问题、
> JS 题库的 `text` / `why` / `refText` 字段、来源的 `<span class="badge">` 与 `<span class="note">`、
> `<div class="meta-card">` 人工核查记录、`<div class="plain">` 通俗理解、SVG 内的文字

并要求它用 Grep 自查。**只写「改辨析表」它就只有辨析表会被改**——实测漏掉其余 6 类位置，
复核时才发现，等于白跑一轮。改完必须重跑本脚本，重点看 `answer` 索引是否因选项文字改写而错位。

## 6. 改课程安排后：一定要跑跨文档一致性

**概念编号 ↔ 课次归属** 至少出现在三个地方，由不同批次的编辑维护，极易漂移：

| 位置 | 形态 |
|---|---|
| 地图 HTML 的概念表 | `<tr><td>13</td><td><a href="...">文本分类</a></td><td>第 3 课</td>` |
| 地图 MD 的概念表 | `\| 13 \| [文本分类](...) \| 第 3 课 \|` |
| 目录页的分课次卡片分组 | `<h3>第 3 课 · …</h3>` 块内的 `<div class="num">概念 13</div>` |

```bash
python "<本 skill 目录>/scripts/check_lesson_assignment.py" \
  <地图 HTML> <地图 MD> <目录页 HTML>
```

退出码 `0` 三处一致，`1` 有分歧，`2` 参数/解析失败。

**为什么必须有这一步**：实测踩过一次——课程安排里第 3 课的课堂产出物是「分类器 + 评估报告」，
但构成它的概念 13「文本分类」、14「模型评估」**三处一起标在第 4 课**。
任何单文档抽查都发现不了，因为三处彼此自洽。是逐条核对「产出物在哪一课 / 前置概念是否真的更早」
时才暴露出来的。

> **判断归属合理性的口径**（脚本不代劳，靠人看）：
> 一个概念的课次不应晚于「用到它的那节课」。先确认每节课的课堂产出物，再看构成该产出物的概念
> 有没有归到更晚的课。

### 本脚本自身的坑

- **「跨课」要先于「第 N 课」判断**：枢纽卡的标题常写成「跨课连接 · 第 4 课之后读」，
  若先跑 `第(\d+)课` 正则会命中标题里的「第 4 课之后读」，把枢纽卡误判成 `L4`。
- **中英混排的列对齐要用显示宽度**（中文算 2 列），并且用 `name + ' '*pad` 而不是
  `name.ljust(pad)`——`ljust` 在字符串本身已超宽时不会补空格，会让表格串行。

## 7. 视觉验收：改完 SVG / 表格，目视确认一次

结构校验查不出「元素出界、文字压框、pill 标记被挤成竖排」这类**渲染层**问题。
凡改过内联 SVG 或表格列宽，都该截图看一眼。

**本机首选：系统自带的 Edge 无头截图**（不需要装任何东西）。

```bash
EDGE="/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"
"$EDGE" --headless --disable-gpu --hide-scrollbars \
        --window-size=1100,1000 \
        --screenshot="<绝对路径>/shot.png" \
        "file:///<URL 编码后的本地路径>"
```

要点：
- **`--screenshot` 必须给绝对路径**，给相对路径会静默失败（不报错、不生成文件）
- 目标 URL 里的中文与空格要做 percent-encoding；用 `pathlib.Path.as_uri()` 最省事
- 只看某一段时，用脚本把该段 HTML 抽出来、套上原文件的 `<style>` 单独渲染成临时页，
  比截整页再裁更清楚（抽段时记得把 `<script>` 去掉，避免勾选状态干扰）
- `agent-browser` 若未安装，**不要为此拉 500MB Chromium**；Edge 已能满足静态渲染验收

**几何自检**（截图之前的廉价前置检查）：解析 `<svg>` 的 `viewBox`，逐个核对所有 `<rect>` 的
`x/y/width/height` 是否落在框内，`<text>` 按「CJK 字号 ×1、其他 ×0.55」粗估宽度看是否溢出。
能提前抓出绝大多数出界问题。

### 一个具体的布局坑

把 pill / badge 标记塞进**宽度百分比很小的表格列**（如 `width:6%`）时，
文字会被逐字换行挤成竖排。修法两条同时上：

```css
.badge-pill { display: inline-block; white-space: nowrap; }   /* 不许列内折行 */
```
再把该列加宽到能容纳最长一行（含 padding）。**加之前先量一下最长标签的实际像素宽，
别只看百分比。** 实测 6% 的列放不下「课前读卡 09–14」，加到 10% 后正常。

卡片格式规范见同目录的 `minute-lesson` skill（13 区块结构 + 题库 JS 状态机）。
本 Skill 只做验收，不定义格式。
