一分钟微课 · MINUTE-LESSON

Skill（技能）

60 秒速读 在 WorkBuddy 里，Skill 是一份「提示词 + 脚本 + 工作流的打包」——告诉 AI 在某种场景下该扮演什么角色、走什么步骤、调用哪些工具。它存在的意义是把一次性对话沉淀成可复用资产，下次同样任务直接调，不用再把上下文重新讲一遍。

学习目标

  • 能用一句话区分「Skill」和「普通 prompt」
  • 能列出 Skill 的三件套：YAML 元数据 / 提示词主体 / 可选脚本
  • 能在 WorkBuddy 项目目录下创建一个项目级 Skill（路径 .workbuddy/skills/<name>/SKILL.md）
  • 能区分用户级 Skill、项目级 Skill 与技能市场 Skill

核心问题

Skill 和「写一段提示词让 AI 照做」有什么区别？
区别在三件事：
  1. 复用性：Skill 是文件，存到项目里能 commit、分享、版本管理；普通提示词是临时输入，丢了就没了。
  2. 结构化：Skill 有 YAML frontmatter，机器可以解析「它在什么时候该被调用」「它的摘要是什么」——AI 不是每次都把全文塞进上下文，只在匹配场景时调用。
  3. 可执行：Skill 不只是文字指令，还可以打包脚本和工作流（订外卖、查股价、读写文件），由 AI 在用户授权下代为执行。
项目级 Skill、用户级 Skill、商店 Skill 怎么选？
项目级 Skill放在仓库根目录的 .workbuddy/skills/<name>/SKILL.md，跟代码一起版本管理——团队成员 clone 项目就有了。最适合和当前项目强相关的工作流。

用户级 Skill放在 ~/.workbuddy/skills/，跨项目复用——比如你常用的「周报生成」「会议纪要」就放这。

商店 Skill（技能市场）是一键安装的预制包，适合通用任务。但安装第三方 Skill 前要审慎校验来源和权限申请——非官方 Skill 可能存在提示词注入或越权。
Skill 启用、关闭、卸载三者什么区别？
启用：Skill 在对话中可以被 AI 自动调用。
关闭：Skill 文件还在，AI 不会调用它，状态随账号同步；随时可以重新启用。
卸载：Skill 文件和开关记录一并删除。
简单说：关闭是「暂停」，卸载是「彻底删除」。WorkBuddy 文档强调「仅启用当前任务所需的技能」是为了减少无关干扰和误调用概率。
自己写的 Skill 别人能用吗？
能。三种方式：① 把 .workbuddy/skills/<name>/ 整个目录打 zip 包，上传给对方导入；② 把项目级 Skill 推到 Git 仓库，对方 clone 后自动可用；③ 发布到技能市场。工作流相关的 Skill 一般建议走项目级路径，因为它的提示词和所在项目的代码、术语耦合。

结构化解释

是什么

WorkBuddy 的官方定义是：Skill 为 WorkBuddy 增加「特定工具能力」——封装一组可执行的脚本与工作流，使 AI 在你的授权下完成具体动作（如发送邮件、订外卖、查询股价、读写文件、调用第三方 API 等）。它本质是一份带 YAML 元数据的 Markdown 文件 (SKILL.md)，加上可选的脚本/模板子文件。

为什么

一个常见的痛点：你花了半小时调好一段提示词让 AI 按你的格式输出周报，但下次开新对话又要重新讲一遍——而且你不知道下次 AI 还会不会照做。Skill 就是为了解决这个问题：把「角色 + 步骤 + 输出格式 + 可选工具调用」打包成文件，存进项目，commit 到 Git，下次直接 @Skill 名字 调用就行。沉淀的不只是提示词，是**带场景标注的可复用知识包**。

怎么工作（一个 Skill 文件长什么样）

最小的 SKILL.md 长这样：

---
title: "周报生成专家"
summary: "把本周碎片任务汇总成结构化周报"
read_when:
  - 用户说"帮我写周报"
  - 用户提供多条零散事项想汇总
---

# 周报生成专家

你是一位资深产品经理的助手。收到一周的零散事项后：

1. 按"目标 / 进展 / 卡点 / 下周计划"四段汇总
2. 每段不超过 5 条 bullet
3. 输出 Markdown，不要寒暄

解析规则：

  • YAML frontmatter（--- 之间）：元数据。title / summary / read_when 都是可选但强烈建议填——AI 用 read_when 决定什么时候主动加载这个 Skill。
  • Markdown 正文：提示词主体，可以是步骤、规则、输出格式。
  • 同名目录下的子文件：可选。比如 scripts/ 放可执行脚本，templates/ 放模板。

应用案例

案例：课程作业里的「minute-lesson」Skill

本仓库就有一个真实的 Skill，路径是 .workbuddy/skills/minute-lesson/SKILL.md。它做的事：

  1. 场景：调用方想「60 秒理解一个新概念」
  2. 输入：概念名（如 Agent、RAG、Skill）
  3. 流程：搜索权威来源 → 按 7 段式大纲填充 → 渲染 HTML → 自检清单
  4. 输出：learning-materials/<slug>.html，单文件、可离线、可分享

如果没有 Skill，调同样的概念你得每次都把「我要 7 段结构、来源要真实、输出 HTML、不要编」重新打一段——而且对方模型未必记得。沉淀成 Skill 之后，这个工作流就可以**无限复用、版本管理、给同学用**，这就是 Skill 的核心价值。

概念辨析

邻近概念 与 Skill 的核心区别 一句话判定
普通 Prompt 临时输入、丢一次就没；Skill 是文件、可复用 「一次性对话」 vs 「打包好的资产」
系统提示词（system prompt） 系统提示是单次请求里的「定调」角色；Skill 是按场景动态加载的「剧本」 「每次都在」 vs 「用到才出现」
插件 / Extension 插件通常有图形界面和独立入口；Skill 是 Markdown 提示词 + 可选脚本，由 AI 在对话中调用 「用户主动开」 vs 「AI 主动调」
Agent Skill 是 Agent 能用的「工具包」之一；Agent 是有决策循环的运行系统 「剧本」 vs 「会按剧本演的演员」

自测题

1.【单选】项目级 Skill 应该放在哪个路径？
答案：C。WorkBuddy 官方文档给出的项目级 Skill 路径是仓库根目录下的 .workbuddy/skills/<name>/SKILL.md，可以随项目一起 commit。
  1. ~/Desktop/skill.md
  2. ./prompts/skill.md
  3. .workbuddy/skills/<name>/SKILL.md
  4. 随便放哪里都行
2.【判断】关闭 Skill 和卸载 Skill 是一回事。
答案：错误。关闭只是暂停 AI 调用，Skill 文件和开关记录都还在；卸载才会删除 Skill 及其开关记录。
3.【简答】SKILL.md 的 YAML frontmatter 推荐包含哪些字段？
答案：根据 WorkBuddy 官方示例：
  • title：Skill 的展示名
  • summary：一句话说明它做什么
  • read_when：触发场景列表（用户说什么话时该调它）
这些字段让 AI 不必每次都把 Skill 全文塞进上下文，只在匹配场景时加载。
4.【开放】请设计一个你自己的 Skill：场景 + 输入 + 三步流程 + 输出格式。
参考思路（示例：错题本整理 Skill）：
  • 场景：每周日晚上，把这一周的错题截图 OCR 后整理
  • 输入：截图 + 当前科目
  • 流程：① OCR 提取文字 ② 按科目+题型分类 ③ 输出 Anki 卡片格式
  • 输出：一份 Markdown，每题一张卡片（正面问题/背面答案）
