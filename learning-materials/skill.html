Skill（技能 / 提示模板）

60 秒速读 Skill 是用 YAML 元数据描述、按需注入 Agent 上下文的可复用指令文件——它把「专家经验」沉淀成结构化模板，让 AI 在合适时机自动加载「怎么想 / 怎么做」的指导，而不是每次对话都重新描述一遍。WorkBuddy 把 Skill 放在仓库内的 .workbuddy/skills/ 下，叫「项目级 Skill」；放在用户目录的叫「用户级 Skill」。

学习目标

  • 能在一句话内区分「Skill」和「普通提示词」、「插件」、「工作流」
  • 能列出 SKILL.md 顶部 YAML 的至少 2 个必备字段
  • 能解释「项目级 Skill」与「用户级 Skill」的优先级与适用场景
  • 能讲清「Skill 的可复用性」为什么是 Agent 工程的关键能力

核心问题

Skill 和「写一段提示词」有什么区别？
提示词是一次性的、临时贴在对话开头的指令；Skill 是结构化、有元数据、能被 Agent 自动识别并按需加载的模块化指令包。一次写好，多次复用——这也是 Skill 存在的全部意义。[1]
Skill 和「插件 / 工具调用」是一回事吗？
不是。Skill 是放在上下文里的指令（告诉 Agent「怎么想、按什么步骤做」）；插件 / 工具是调用外部功能的代码（让 Agent 能查数据库、读写文件）。Skill 可以指导 Agent 去使用工具，但两者不在同一层。[2]
WorkBuddy 的项目级 Skill 放在哪里？
放在仓库根目录的 .workbuddy/skills/<skill-name>/SKILL.md。每个 Skill 一个目录，目录里 SKILL.md 是入口文件。同一个 Skill 还能附带模板、脚本、参考文档。[1]
SKILL.md 顶部 YAML 的 name 和 description 字段为什么是必备？
name 是 Skill 在 Agent 上下文里的标识；description 是触发条件——Agent 按这段描述判断「这件事我该不该加载这个 Skill」。缺这两个字段，Agent 就无法把 Skill 正确路由到合适的任务上。[1]

结构化解释

理解「Skill」需要把握四件事：

  1. Skill 本质是一份带 YAML 元数据的 Markdown 指令文件。YAML 描述「我是谁、何时该被加载」，Markdown 正文才是真正的「怎么想、怎么做」指引。例：[1] 
    ---
name: minute-lesson
description: 用「60 秒速读 + 8 题互动自测」格式生成任意概念的微课。
---

# minute-lesson · 一分钟微课生成器

## 适用场景
需要为一个新概念快速写出可分享、可自测的学习资料。
...
  2. Skill 按需注入上下文。所有 Skill 不会一次性堆进上下文——Agent 按 YAML 中的 description（和可选的 read_when）判断是否需要加载。这样即使你装了 50 个 Skill，也不会挤爆上下文窗口。[2]
  3. Skill 是沉淀「专家经验」的容器。一次写好的 Skill 可以被新员工、新 Agent 反复使用，是把「团队里某个人会的招」变成「团队里大家都有的招」的标准做法。这也是 Anthropic 在 2025 年力推 Skills 概念的核心理由。[2]
  4. WorkBuddy 分项目级和用户级。项目级 Skill 在 .workbuddy/skills/，随仓库走、随项目场景定制；用户级 Skill 在 ~/.workbuddy/skills/，跨项目复用个人习惯。同名时项目级优先，因为它跟当前工作目录匹配得更紧。[1]
一句话记住 Skill = 一份有结构、可被 Agent 自动加载、可反复复用的指令模板。 它的价值不在「一次性写一条提示」，而在把经验沉淀成可调用模块。

应用案例

案例 1：本仓库的 minute-lesson Skill

你正在看的三张微课，就是用项目根目录的 .workbuddy/skills/minute-lesson/SKILL.md 生成的。它的设计要点：

  • 唯一必填参数是「学习主题」，从而能复用于任何概念，不限于 Agent / 上下文 / Skill 三个概念；
  • 内置自检清单（8 条），AI 起草完会自己逐项核查再输出；
  • 附录 HTML 模板 + 概念大纲文档，方便后续迭代。

这就是 Skill 的核心价值：把「怎么写一张高质量学习卡」这件事模块化、可调用、可协作修改。[1]

案例 2：Anthropic 官方的 Skills 体系

Anthropic 在 2025 年公开了 Skills / Claude Skills 的设计：每个 Skill 是一个文件夹，内含 SKILL.md（主入口）+ 任意附属文件。Claude 在合适任务下自动加载这些 Skill，把团队里积累的工作流沉淀成可复用资产。[2]

概念辨析 / 使用边界

易混项 正解
Skill = 插件 = 工具调用 Skill 是上下文里的指令；插件/工具是 Agent 能调用的外部功能。
Skill = System Prompt System Prompt 每次都强制加载；Skill 按 description/read_when 按需加载。
Skill 必须用 Python 写 不需要。Skill 是 Markdown + YAML，代码只是附属，可纯文本就能跑。
Skill 越多越好 不。多到 Agent 路由混乱，不如少而精；关注 description 是否互相重叠。
写错 Skill 要回炉重做 可以叠加「外层 wrapper Skill」做兜底，在出错时给 Agent 追加补充指令。[2]
