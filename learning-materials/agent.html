Agent（智能体）

60 秒速读 Agent 是一种能在最少人类干预下，代替用户自主完成多步任务的系统——它通常由一个大模型驱动，能调用外部工具，并能根据执行结果动态决定下一步做什么。它和「普通 AI 对话」最大的区别是：能 行动，而不只是回答。
🌱 我的理解

我一开始以为 Agent 就是 ChatGPT 加几个 API，后来才分清差别在会不会自己做决定：ChatGPT 是你问一句、它答一句；Agent 是你给它一个目标，它自己拆步骤、查资料、动手干。

最直观的比喻：聊天像翻菜单点菜，Agent 像跟朋友说「我饿了」，他决定吃什么。

学习目标

  • 能用一句话给「Agent」下一个能区分 AI 对话、Copilot、Agent 的定义
  • 能列出 Agent 的三件套（模型 / 工具 / 指令）和典型工作循环
  • 能用真实例子讲清「什么场景适合用 Agent，什么场景用规则引擎就够了」
  • 能区分 Workflows 和 Agents 这两个常被混用的概念

核心问题

Agent 和普通的「AI 聊天」有什么区别？
AI 聊天本质是「你问一句，它答一句」，模型只能产出文字，不能调用外部系统。Agent 则会主动调用工具（查数据库、读写文件、调用 API）并根据工具返回的结果继续决定下一步——它的「回答」可能是一段文字，也可能是一次操作的结果。OpenAI 的官方定义就把这种「能在用户授权下代替用户行动」的能力作为 Agent 的关键特征。[3]
Agent 必须能完全自主思考吗？
不一定。Anthropic 把 Agent 和 Workflow 区分开来：Workflow 是用预定义代码路径把 LLM 和工具串起来的系统（人设计流程，LLM 填空）；Agent 则是 LLM 动态决定流程怎么走、什么时候用哪个工具的系统。两个都属于「agentic systems」（智能体系统），但自主程度不同。[2]
Agent 是不是「AGI 的雏形」？
经常被营销话术这么说，但更准确的理解是：Agent 是当前大模型能力（推理、工具调用、长上下文）落地到具体任务的一种工程形态。它没有意识，也不会真的「思考」，只是把决策循环（观察→决策→行动→再观察）做成了可运行的程序。把它当工具看，不要当生命看。
Agent 一定要联网吗？
联网是常见做法，但不是定义属性。一个 Agent 只要能「感知环境、做出决策、施加行动」，闭环就成立。环境可以是本地文件系统、本地数据库、IDE，也可以是互联网。在内网/隔离环境里照样能跑 Agent。Russell & Norvig 在经典教材里把 agent 定义为「能通过传感器感知环境、并通过执行器作用于环境的实体」，范围远不止联网。[4]

结构化解释

是什么

Agent（智能体）是一种软件系统：它感知自己所处的环境，调用工具执行动作，并根据动作结果自主决定下一步该做什么，直到完成用户给它的目标。Russell 和 Norvig 在经典教材《人工智能：现代方法》里给出的最广义定义是「任何能通过传感器感知环境、并通过执行器作用于环境的实体」，从恒温器到人都是 Agent。[4]

为什么

传统软件走「确定性路径」——规则固定，输入相同输出就相同。但很多现实任务（审批退款、分析保险索赔、排查代码 bug）规则写不完、判断依赖语境。Agent 的价值在于把「判断 + 执行」合在一起：让 LLM 当决策中心，把规则交给工具，结果由 LLM 在循环中动态组合。

OpenAI 在 2025 年发布的《A Practical Guide to Building Agents》里给出了一个判断标准：如果一个用例「之前用传统自动化做不到」，又涉及自然语言/模糊判断/多步推理，就适合做 Agent；否则可能只需要一个普通脚本。[1]

怎么工作（典型循环）

  1. 感知：读系统提示、当前对话/任务、上一步工具返回结果
  2. 推理：由 LLM 判断「现在该调用哪个工具、传什么参数、还是该给最终回答」
  3. 行动：调用外部工具（API、数据库、文件、代码执行器等）[1]
  4. 再感知：把工具结果塞回上下文，让模型接着判断[2]
  5. 终止判断：任务完成 → 输出最终结果；多次失败 → 把控制权交回用户

OpenAI 把它浓缩成三件套：Model + Tools + Instructions。Anthropic 的 Agents SDK 同理：模型负责决策，工具负责执行，指令（系统提示 + 护栏）负责约束行为边界。[1]

⚠ 常见误区把 Agent 等同于 Copilot 或单纯的「AI 自动化」是新人最易踩的坑，辨析详见 Lilian Weng 综述[5]。

应用案例

案例 1：客服退款审批 Agent

OpenAI 在指南里给的一个具体例子：用户申请退款，按传统做法需要客服在后台看订单、判断是否符合政策、决定金额；规则一多就维护不过来。改成 Agent 后，模型读用户订单数据（感知），根据退款政策判断是否满足条件（推理），调用支付系统发起退款或调用工单系统转人工（行动），把结果回写到对话历史（再感知）。[1]

关键不是「用 AI 替代人」，而是「用 AI 接管规则变化快、判断需要看上下文的那些环节」。整套系统仍然有 guardrails：单笔退款超过 1000 元必须转人工、同一用户 24 小时内超过 3 次自动冻结。

概念辨析

邻近概念 与 Agent 的核心区别 一句话判定
普通 AI 对话 / Chatbot 没有工具调用，只能产出文字 「能说」但「不能做」
Copilot / 助手 提供建议，由人决定是否采纳；Agent 是自己决定并执行 「我建议…」vs「我做了…」
Workflow（工作流） 由预定义代码路径串联 LLM 和工具，Agent 是 LLM 动态决定流程[2] 「剧本写好 LLM 演」vs「让 LLM 自己决定剧本」
传统规则引擎 规则固定、判断确定；Agent 用 LLM 处理模糊判断 「if-else 走天下」vs「能读懂自然语言的 if-else」
